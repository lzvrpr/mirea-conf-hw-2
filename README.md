# Этап 1. Минимальный прототип с конфигурацией

Практическая работа №2, вариант №16, этап 1.
Реализация: Python 3.9+, только стандартная библиотека.

## 1. Общее описание

Инструмент визуализации графа зависимостей пакетного менеджера. На этом этапе
он ещё не собирает зависимости: приложение разбирает параметры командной
строки, проверяет каждый из них и печатает все параметры в формате
ключ-значение — это отладочный вывод, которого требует задание.

Что уже работает:

- пять настраиваемых параметров: имя пакета, URL репозитория, файл тестового
  репозитория, режим работы с тестовым репозиторием, вывод деревом и
  максимальная глубина анализа;
- каждый параметр проверяется до запуска анализа, на ошибку печатается
  сообщение и возвращается код 2;
- режим и источник данных согласованы: `real` работает с URL, `test` — с
  файлом, смешивать их нельзя;
- все параметры печатаются в формате `ключ: значение`, незаданные отмечены
  словами «не задан».

Осознанные ограничения этапа:

- зависимости не собираются: ни сеть, ни файл тестового репозитория пока не
  читаются по существу, проверяется только то, что файл существует и читается
  в UTF-8;
- формат файла тестового репозитория появится на этапе 3, здесь он не
  разбирается;
- параметр `--tree` только сохраняется и печатается, вывод деревом
  реализуется на этапе 5.

## 2. Функции и настройки

Параметры командной строки:

- `--package ИМЯ` — имя анализируемого пакета, обязательный. Допустимы
  латинские буквы, цифры, точка, дефис и подчёркивание; имя не может
  начинаться или заканчиваться точкой, дефисом или подчёркиванием
  (правила PEP 508). Пробелы по краям обрезаются;
- `--repo URL` — URL-адрес репозитория пакетов. Обязателен в режиме `real`:
  схема только `http` или `https`, имя хоста обязательно;
- `--repo-file ПУТЬ` — путь к файлу тестового репозитория. Обязателен в режиме
  `test`: файл должен существовать, быть обычным файлом и читаться в UTF-8;
- `--mode {real,test}` — режим работы с тестовым репозиторием. `real` —
  данные берутся из реального репозитория по `--repo`, `test` — из файла
  `--repo-file`. По умолчанию `real`;
- `--tree` — выводить зависимости в виде ASCII-дерева; по умолчанию вывод
  плоским списком;
- `--depth N` — максимальная глубина анализа зависимостей, целое число от 1
  до 20, по умолчанию 3. Верхняя граница защищает от случайного обхода
  огромного графа;
- `-h`, `--help` — подсказка по параметрам, её печатает argparse.

Взаимоисключение источника: в режиме `test` параметр `--repo` запрещён, в
режиме `real` запрещён `--repo-file`. Так пользователь не запутается, какой
источник данных реально используется.

Состав файлов:

- `main.py` — точка входа: разбор параметров, печать, код выхода;
- `src/config.py` — разбор параметров (`Config.from_argv`) и их проверка
  (`_check_package`, `_check_depth`, `_check_repo`, `_check_repo_file`,
  `_check_test_source`, `_check_real_source`), отладочный вывод
  (`Config.describe`), исключение `ConfigError`;
- `tests/test_config.py` — тесты разбора и всех проверок;
- `tests/data/minimal-repo.txt` — маленький файл тестового репозитория для
  проверки параметра `--repo-file`;
- `run.sh`, `run.bat` — запуск приложения в Linux/macOS и в Windows.

Коды выхода: `0` — параметры верны, `2` — ошибка в параметрах (как у argparse).

## 3. Сборка и запуск тестов

Нативной сборки нет, сторонних зависимостей тоже: нужен только Python 3.9+.

```
python3 -m unittest discover -s tests
```

Ожидаемый результат: `Ran 28 tests` и `OK`.

Запуск приложения:

```
./run.sh --help
```

## 4. Примеры использования

Все параметры сразу:

```
$ ./run.sh --package requests --repo https://pypi.org/pypi --tree --depth 4
пакет: requests
режим: real
URL репозитория: https://pypi.org/pypi
файл тестового репозитория: не задан
вывод деревом: да
максимальная глубина: 4
```

Тестовый репозиторий и значения по умолчанию:

```
$ ./run.sh --package A --mode test --repo-file tests/data/minimal-repo.txt
пакет: A
режим: test
URL репозитория: не задан
файл тестового репозитория: tests/data/minimal-repo.txt
вывод деревом: нет
максимальная глубина: 3
```

Обработка ошибок:

```
$ ./run.sh --package bad/name --repo https://pypi.org/pypi
ошибка: недопустимое имя пакета 'bad/name': допустимы латинские буквы,
цифры, точка, дефис и подчёркивание

$ ./run.sh --package requests --repo pypi.org/pypi
ошибка: URL репозитория 'pypi.org/pypi' должен начинаться с http:// или
https://

$ ./run.sh --package requests --repo https://pypi.org/pypi --depth 0
ошибка: глубина анализа не может быть меньше 1: 0

$ ./run.sh --package A --mode test
ошибка: в режиме test нужен --repo-file

$ ./run.sh --package A --mode test --repo-file tests/data/nope.txt
ошибка: файл тестового репозитория не найден: tests/data/nope.txt

$ ./run.sh --package requests --repo https://pypi.org/pypi --mode cloud
dependency-graph: error: argument --mode: invalid choice: 'cloud'
(choose from 'real', 'test')
```

Во всех случаях с ошибкой код выхода — 2.
