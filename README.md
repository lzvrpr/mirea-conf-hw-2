# Этап 4. Дополнительные операции

Практическая работа №2, вариант №16, этап 4.
Реализация: Python 3.9+ и aiohttp — обход и запросы асинхронные.

## 1. Общее описание

Добавлен режим обратных зависимостей: для заданного пакета печатаются пакеты,
которые от него зависят. Обход — тот же алгоритм DFS с рекурсией, что и на
этапе 3, только идёт он по инвертированным рёбрам: вместо «от кого зависит
пакет» берутся «кто зависит от пакета».

Что уже работает:

- флаг `--reverse` переключает приложение на обратный обход;
- обратный граф строится из рёбер тестового репозитория, поэтому видны все
  цепочки: для `SHARED` находятся `LEFT` и `RIGHT`, а за ними `ROOT`;
- ограничение глубины и пометки `(цикл)`, `(глубина)` работают так же, как в
  прямом обходе: обратный граф может содержать циклы;
- прямой обход по умолчанию не изменился.

Осознанное ограничение этапа:

- обратные зависимости строятся только по тестовому репозиторию. У PyPI нет
  обратного индекса «кто зависит от пакета»: чтобы получить его честно, нужно
  скачать и разобрать весь индекс пакетов, а это уже не визуализация графа,
  а построение зеркала. При `--mode real --reverse` приложение так и говорит и
  возвращает код 2.

## 2. Функции и настройки

Новый параметр:

- `--reverse` — вывести обратные зависимости: пакеты, которые зависят от
  пакета из `--package`. Работает в режиме `test`, в режиме `real`
  отвергается с кодом 2.

Остальные параметры прежние: `--package`, `--repo`, `--repo-file`, `--mode`,
`--depth`, `--tree`.

Состав файлов (изменения относительно этапа 3):

- `src/graph.py` — у `DependencyGraph` появился метод `parents`: пакеты,
  которые зависят от заданного, по алфавиту;
- `src/config.py` — разбор и хранение флага `--reverse`, строка о нём в
  отладочном выводе;
- `main.py` — `run_forward` и `run_reverse`: обратный обход использует
  `build_tree` с источником `graph.parents`;
- `tests/test_main.py` — интеграционные тесты запуска: прямой обход, обратный
  обход, цепочка до корня, пакет без обратных зависимостей, отказ в режиме
  real;
- остальные тесты и примеры без изменений.

Коды выхода: `0` — успех, `2` — ошибка в параметрах (в том числе `--reverse`
в режиме real), `3` — ошибка репозитория или файла тестового репозитория.

## 3. Сборка и запуск тестов

```
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Тесты:

```
python3 -m unittest discover -s tests
```

Ожидаемый результат: `Ran 87 tests` и `OK`.

## 4. Примеры использования

Обратные зависимости `SHARED` в `examples/branching.txt`: от него зависят
`LEFT` и `RIGHT`, а от них — `ROOT`.

```
$ ./run.sh --package SHARED --mode test --repo-file examples/branching.txt \
    --reverse --depth 3
обратные зависимости пакета SHARED, глубина до 3:
SHARED
  LEFT
    ROOT
  RIGHT
    ROOT
узлов: 5, циклов: 0, с ошибкой: 0, обрезано по глубине: 0
```

Тот же граф, но вопрос задан про `BASE` — цепочка длиннее на один уровень:

```
$ ./run.sh --package BASE --mode test --repo-file examples/branching.txt \
    --reverse --depth 4
обратные зависимости пакета BASE, глубина до 4:
BASE
  SHARED
    LEFT
      ROOT
    RIGHT
      ROOT
узлов: 6, циклов: 0, с ошибкой: 0, обрезано по глубине: 0
```

Цепочка из `examples/linear.txt`: обратные зависимости `D` — это `C`, `B`, `A`.

```
$ ./run.sh --package D --mode test --repo-file examples/linear.txt \
    --reverse --depth 5
обратные зависимости пакета D, глубина до 5:
D
  C
    B
      A
узлов: 4, циклов: 0, с ошибкой: 0, обрезано по глубине: 0
```

У корневого пакета обратных зависимостей нет:

```
$ ./run.sh --package ROOT --mode test --repo-file examples/branching.txt \
    --reverse
обратные зависимости пакета ROOT, глубина до 3:
ROOT
узлов: 1, циклов: 0, с ошибкой: 0, обрезано по глубине: 0
```

Режим real:

```
$ ./run.sh --package requests --repo https://pypi.org/pypi --reverse
ошибка: обратные зависимости строятся только по тестовому репозиторию:
у репозитория PyPI нет обратного индекса
```
