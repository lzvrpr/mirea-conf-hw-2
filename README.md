# Этап 3. Основные операции

Практическая работа №2, вариант №16, этап 3.
Реализация: Python 3.9+ и aiohttp — обход и запросы асинхронные.

## 1. Общее описание

Приложение строит граф зависимостей пакета с учётом транзитивности и печатает
его деревом. Обход — алгоритм DFS с рекурсией: узел раскрывается, затем
рекурсивно раскрываются его дети. Источников данных два:

- **real** — метаданные пакетов запрашиваются у репозитория PyPI по URL;
- **test** — граф читается из файла тестового репозитория, пакеты в нём
  названы большими латинскими буквами.

Что уже работает:

- рекурсивный обход в глубину с построением дерева зависимостей;
- ограничение максимальной глубины: на последнем уровне узлы помечаются
  `(глубина)` и дальше не раскрываются;
- распознавание циклов: имя, которое уже встречалось выше по пути от корня,
  помечается `(цикл)` и не раскрывается — рекурсия не уходит в бесконечность;
- одинаковый пакет в разных ветках — это не цикл, а обычное повторение;
- ошибка получения зависимостей отдельного пакета не роняет обход: узел
  помечается `(зависимости не получены)`, остальные ветки строятся дальше;
- сводка по дереву: число узлов, циклов, ошибок и обрезанных по глубине узлов.

Осознанные ограничения этапа:

- в граф входят базовые зависимости; зависимости из extras (`pip install
  name[extra]`) не входят, потому что при обычной установке они не ставятся;
- маркеры окружения (`python_version < "3.10"`) не вычисляются: зависимость
  считается присутствующей;
- повторная загрузка метаданных одного пакета в пределах запуска не
  выполняется: источник кэширует ответы в памяти;
- изображение графа и вывод деревом в формате ASCII появятся на этапе 5.

## 2. Функции и настройки

Параметры командной строки:

- `--package ИМЯ` — имя анализируемого пакета, обязательный;
- `--repo URL` — база репозитория для режима real;
- `--repo-file ПУТЬ` — файл тестового репозитория для режима test;
- `--mode {real,test}` — источник зависимостей;
- `--depth N` — максимальная глубина обхода, 1…20, по умолчанию 3. Глубина 1
  означает «только прямые зависимости», 2 — «прямые и их прямые» и так далее;
- `--tree` — пока не влияет: печать деревом в формате ASCII — этап 5.

Формат файла тестового репозитория:

```
# строка, начинающаяся с решётки, — комментарий
A B
B C
```

Каждая строка — ребро «A зависит от B». Имена пакетов — большие латинские
буквы, цифры, дефис и подчёркивание. Пустые строки пропускаются. Строка не из
двух имён или имя в другом регистре — ошибка с номером строки. Файл без
единственной зависимости — тоже ошибка.

Состав файлов:

- `main.py` — точка входа: выбор источника, построение дерева, печать;
- `src/config.py` — параметры командной строки и их проверка;
- `src/graph.py` — `Node` (узел дерева с пометками и обходом `walk`),
  `DependencyGraph` (хранение рёбер), `build_tree` (DFS с рекурсией),
  `DependencyError`;
- `src/pypi.py` — загрузка метаданных, `PyPiProvider` с кэшем в памяти;
- `src/requirement.py` — разбор строк PEP 508;
- `src/report.py` — плоский список зависимостей, печать дерева с отступами,
  сводка;
- `src/test_repo.py` — чтение файла тестового репозитория и проверка формата;
- `examples/` — файлы тестовых репозиториев: `linear.txt`, `branching.txt`,
  `cycle.txt`, `deep.txt`, `broken.txt`;
- `tests/` — тесты, 84 штуки.

Коды выхода: `0` — успех, `2` — ошибка в параметрах, `3` — ошибка
репозитория или файла тестового репозитория.

## 3. Сборка и запуск тестов

```
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Тесты:

```
python3 -m unittest discover -s tests
```

Ожидаемый результат: `Ran 81 tests` и `OK`.

## 4. Примеры использования

Цепочка из `examples/linear.txt`:

```
$ ./run.sh --package A --mode test --repo-file examples/linear.txt --depth 5
дерево зависимостей пакета A, глубина до 5:
A
  B
    C
      D
узлов: 4, циклов: 0, с ошибкой: 0, обрезано по глубине: 0
```

Та же цепочка с глубиной 2 — обход останавливается на третьем уровне:

```
$ ./run.sh --package A --mode test --repo-file examples/linear.txt --depth 2
дерево зависимостей пакета A, глубина до 2:
A
  B
    C (глубина)
узлов: 3, циклов: 0, с ошибкой: 0, обрезано по глубине: 1
```

Ветвление из `examples/branching.txt`: пакет `SHARED` встречается в двух
ветках, и это не цикл.

```
$ ./run.sh --package ROOT --mode test --repo-file examples/branching.txt
дерево зависимостей пакета ROOT, глубина до 3:
ROOT
  LEFT
    SHARED
      BASE (глубина)
  RIGHT
    SHARED
      BASE (глубина)
узлов: 7, циклов: 0, с ошибкой: 0, обрезано по глубине: 2
```

Цикл из `examples/cycle.txt`:

```
$ ./run.sh --package A --mode test --repo-file examples/cycle.txt --depth 5
дерево зависимостей пакета A, глубина до 5:
A
  B
    C
      A (цикл)
узлов: 4, циклов: 1, с ошибкой: 0, обрезано по глубине: 0
```

Ошибки:

```
$ ./run.sh --package A --mode test --repo-file examples/broken.txt
ошибка: строка 3: нужно два пакета через пробел: 'B'

$ ./run.sh --package ZZZ --mode test --repo-file examples/linear.txt
ошибка: пакета 'ZZZ' нет в тестовом репозитории
```

Реальный репозиторий — видна транзитивность через `importlib-metadata`:

```
$ ./run.sh --package flask --repo https://pypi.org/pypi --depth 2
дерево зависимостей пакета flask, глубина до 2:
flask
  blinker
  click
  importlib-metadata
    zipp (глубина)
    lazy-importer (глубина)
  itsdangerous
  jinja2
    MarkupSafe (глубина)
  markupsafe
  werkzeug
    markupsafe (глубина)
узлов: 12, циклов: 0, с ошибкой: 0, обрезано по глубине: 4
```
