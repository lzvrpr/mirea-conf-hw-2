# Этап 2. Сбор данных

Практическая работа №2, вариант №16, этап 2.
Реализация: Python 3.9+ и aiohttp — запросы к репозиторию асинхронные.

## 1. Общее описание

К прототипу этапа 1 добавлен сбор данных: приложение получает метаданные
заданного пакета из репозитория PyPI и печатает все прямые зависимости этого
пакета. Ни менеджеры пакетов, ни сторонние библиотеки не используются —
запрос идёт через стандартный `urllib.request`, ответ разбирается стандартным
`json`.

Что уже работает:

- загрузка метаданных пакета по адресу `<URL репозитория>/<пакет>/json`;
- разбор строк зависимостей в формате PEP 508: имя, ограничение версии,
  extras в квадратных скобках, маркер окружения после точки с запятой;
- различение базовых зависимостей и зависимостей из extras: у последних в
  маркере есть `extra == "..."`, при выводе они помечены;
- вывод всех прямых зависимостей по алфавиту с итоговой сводкой;
- обработка ошибок репозитория: 404, прочие коды HTTP, недоступная сеть,
  не-JSON ответ, ответ без блока `info`.

Осознанные ограничения этапа:

- анализируются только прямые зависимости: транзитивные появятся на этапе 3;
- маркеры версии Python (`python_version < "3.10"`) не вычисляются, а
  показываются как маркер окружения;
- режим `test` пока сообщает, что файл тестового репозитория начнёт
  разбираться на этапе 3;
- параметры `--tree` и `--depth` сохраняются, но на этом этапе не влияют на
  вывод: дерево и ограничение глубины — этапы 3 и 5.

## 2. Функции и настройки

Параметры командной строки те же, что на этапе 1:

- `--package ИМЯ` — имя анализируемого пакета, обязательный;
- `--repo URL` — база репозитория, например `https://pypi.org/pypi`. Адрес
  метаданных собирается как `<URL>/<пакет>/json`;
- `--repo-file ПУТЬ` — путь к файлу тестового репозитория (обязателен в режиме
  `test`, разбор файла — этап 3);
- `--mode {real,test}` — режим работы: `real` тянет данные из репозитория,
  `test` пока только сообщает о будущем разборе файла;
- `--tree` — вывод деревом (этап 5);
- `--depth N` — максимальная глубина анализа, 1…20, по умолчанию 3 (этап 3).

Состав файлов:

- `main.py` — точка входа: разбор параметров, сбор зависимостей, печать отчёта;
- `src/config.py` — параметры командной строки и их проверка;
- `src/pypi.py` — `build_url` (адрес метаданных), `fetch_metadata` (запрос и
  разбор ответа), исключение `RepositoryError`;
- `src/requirement.py` — `parse_requirement` (разбор строки PEP 508), класс
  `Requirement` с полями `name`, `extras`, `specifier`, `marker` и свойствами
  `extra` и `describe`, функции `direct_dependencies` и `normalize_name`;
- `src/report.py` — `format_report`: сортировка зависимостей и итоговая строка;
- `tests/test_config.py`, `tests/test_pypi.py`, `tests/test_requirement.py`,
  `tests/test_report.py` — тесты;
- `tests/data/requests.json` — сохранённый ответ репозитория, чтобы тесты не
  зависели от сети; `tests/data/minimal-repo.txt` — файл для `--repo-file`.

Коды выхода: `0` — успех, `2` — ошибка в параметрах, `3` — ошибка
репозитория (пакет не найден, нет сети, неверный ответ).

## 3. Сборка и запуск тестов

Нативной сборки нет: нужен Python 3.9+ и библиотека aiohttp.

```
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

```
python3 -m unittest discover -s tests
```

Ожидаемый результат: `Ran 54 tests` и `OK`.

Запуск приложения:

```
./run.sh --package requests --repo https://pypi.org/pypi
```

Обработка ошибок:

```
$ ./run.sh --package no-such-package-xyz-42 --repo https://pypi.org/pypi
ошибка: пакет 'no-such-package-xyz-42' не найден в репозитории (HTTP 404)

$ ./run.sh --package requests --repo https://no-such-host-xyz.invalid/pypi
ошибка: репозиторий недоступен: [Errno -2] Name or service not known
```

В обоих случаях код выхода — 3.
